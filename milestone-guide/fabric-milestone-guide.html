Fabric Delivery Guide — the milestones, explained

For every item in the plan: what it means in Fabric (concept, not deep tech) and how we control it. Some items our platform already handles; others are standards we recommend BCPC adopt.

PlatformBuilt in our platformOur config-as-code control plane already does this.
StandardRecommended standardA governance/operating decision to adopt — policy, not code.
BothPlatform + standardThe platform provides the mechanism; a standard sets the policy.
Our control plane is the config-as-code framework we built on Fabric: declare what to load and how to govern it, and it connects, ingests, cleanses, quality-checks, models, and secures the data across DEV / UAT / PROD. Wherever you see Platform, that's what's working.

Milestone 1

Fabric Platform Foundation

Stand up the infrastructure, governance, security, architecture, and operating framework everything else runs on.

Establish Fabric Infrastructure Foundation

The physical footing: the compute we buy, the network path to our data, and the replication options.

ItemWhat it means in FabricHow we control it
Provision Fabric CapacityThe compute + storage tier (an F-SKU) that powers every workspace, pipeline, and report.StandardSize an F-SKU to the workload and assign it to the project workspaces; our provisioning script stands up everything on it, identically per environment.
Configure Capacity AdministrationAdmin controls for the capacity — who manages it, feature switches, workload limits, surge protection.StandardA named capacity-admin group manages it in the Admin portal; we recommend surge-protection and throttling guardrails.
Deploy Fabric Data GatewaySoftware that lets Fabric reach data behind a private network (on-prem or private OCI/Azure).BothOur ingestion routes private sources through the gateway; we documented the architecture, including reusing the existing VNet gateway.
Validate Gateway ConnectivityConfirming Fabric can actually reach a source through the gateway.StandardA "test connection" per source before onboarding, plus a documented checklist (firewall, DNS, service account).
Review Gateway ArchitectureChoosing gateway type and network path (VNet vs on-premises data gateway).PlatformWe produced the private-OCI diagrams — framework path via the VNet gateway, mirroring path via a dedicated on-prem gateway.
Validate SQL MI Mirroring ArchitectureConfirming near-real-time mirroring works for Azure SQL Managed Instance.BothMirroring is Microsoft-managed; we mapped how a mirrored DB feeds Silver/Gold and recommend it for specific tables.
Assess Oracle Mirroring FeasibilityWhether Oracle mirroring fits (prerequisites, limits, cost, promotion).PlatformDelivered as our Bronze vs Mirroring analysis — GA status, invasive prerequisites, limits, gateway needs, recommendation.
Document Infrastructure ArchitectureA written, shared picture of the platform's infrastructure.PlatformThe architecture diagrams and this guide are that documentation, versioned in the repo.

Define Fabric Data Governance Framework

Who owns the data and how its quality, meaning, lineage, and lifecycle are managed.

ItemWhat it means in FabricHow we control it
Define Data Domain Ownership ModelWhich business area owns which data.StandardData domains map to business areas with a named domain owner accountable for the data within.
Define Data Steward ResponsibilitiesThe people who curate meaning, quality, and access for a data area.StandardA steward role per domain — owns definitions, quality rules, and access decisions.
Define Data Product Ownership ModelTreating governed datasets as "products" with an owner and consumers.StandardGold outputs are the data products; each has an owner, a documented purpose, and a consumer contract.
Define Metadata Management ApproachHow we capture what data exists, its schema, and its meaning.BothThe platform captures technical metadata (sources, schemas, drift, runs); the OneLake catalog + a glossary standard add business meaning.
Define Data Quality StandardsThe rules that decide whether data is fit to use.PlatformDeclarative rules (not-null, ranges, allowed values, expressions) run on the way to Silver; failing rows are quarantined off the clean layer.
Define Data Lineage RequirementsTracing where data came from and what it feeds.BothFabric's built-in lineage view, plus our audit tables recording every source→bronze→silver→gold run.
Define Data Lifecycle StandardsRetention, history, and archival over time.BothBronze is append-only history; Silver/Gold hold current + modelled history (SCD); a retention standard sets how long each is kept.
Define Data Sharing StandardsSharing data across teams without copying it.StandardPrefer OneLake shortcuts / sharing over copies, governed by access + certification, so there's one trusted copy.

Define Fabric Security Framework

Who can see what — access narrows from the whole workspace down to the row, column, and masked value.

Entra security groups — access granted to groups, not people
Workspace roles — Admin / Member / Contributor / Viewer
Lakehouse access — which tables
Row & column security — filter rows · hide columns
Data masking — dynamic + static
ItemWhat it means in FabricHow we control it
Define Entra Security Group StrategyUsing Microsoft Entra ID groups (not individuals) to grant access.BothAccess is granted to Entra groups; our security config references them, so membership — not per-person edits — drives access.
Define Workspace Access ModelThe workspace roles that set broad access.StandardA least-privilege role mapping per workspace, assigned to Entra groups and reviewed on a cadence.
Define Lakehouse Access ModelFine-grained access to tables/columns/rows within a lakehouse.PlatformApplied from config as OneLake column- and row-level security — enforced consistently per environment.
Define Row-Level Security StandardsRestricting which rows a user sees (e.g. by region or plan).PlatformRow filters declared in config and applied by the framework, so the same rule ships to every environment.
Define Data Masking RequirementsHiding or obscuring sensitive values (e.g. SIN, salary).PlatformDynamic masking at query time plus static masking during processing — sensitive columns can be masked, or never land raw.
Define Audit RequirementsRecording who did what, and what the pipeline did.BothFabric's tenant audit logs for user activity, plus our run/quality/drift audit tables for the pipeline itself.
Define Compliance RequirementsMeeting BCPC's regulatory and privacy obligations.StandardMap controls (access, masking, audit, residency) to obligations; the platform's security + audit features provide the evidence.

ItemWhat it means in FabricHow we control it
Define Bronze / Silver / Gold ArchitectureThe medallion pattern: raw → cleaned/conformed → business-ready.PlatformThe spine of the control plane — Bronze (raw, append-only), Silver (deduped, quality, masked), Gold (star schema).
Define Lakehouse vs Warehouse GuidanceWhen to use a Lakehouse (files+tables, Spark) vs a Warehouse (T-SQL).StandardDefault to Lakehouse for the medallion; reach for a Warehouse only where a pure T-SQL surface is required.

Define Transformation PatternsThe approved ways data is cleaned and modelled.PlatformConfig-driven cleanse + quality into Silver, and SQL transforms into a Gold star schema with SCD history.
